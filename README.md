# Bank Marketing ML Service

Сервис предсказывает, подпишется ли клиент банка на срочный депозит. Целевая переменная `y` в исходном CSV принимает значения `yes` и `no`; сервис возвращает `prediction` (`1` или `0`) и `probability` — вероятность класса `1`.

Проект состоит из двух отдельных контейнеров:

- **Inference** — постоянно работающий FastAPI-сервис с эндпоинтами предсказания, проверки состояния и смены модели.
- **Train** — запускаемая по требованию задача. Она читает CSV, обучает модель, проверяет ROC-AUC и при успешной проверке активирует новую версию в Inference. После выполнения контейнер завершается.

Оба сервиса используют общую функцию подготовки признаков и общий каталог `model_registry/`.

## Структура

```text
data/raw/                    исходный CSV для обучения
model_registry/              версии моделей и active_model.txt
src/bank_marketing_service/
  dataset.py                 чтение и подготовка обучающих данных
  preprocessing.py           общая обработка признаков и sklearn-препроцессор
  train.py                   обучение, проверка метрики и активация модели
  inference.py               FastAPI-приложение
  registry.py                сохранение и загрузка моделей
  schemas.py                 Pydantic-схемы запросов и ответов
  settings.py                загрузка и проверка настроек из окружения
tests/                       тесты ключевых сценариев
Dockerfile                   образ для обоих сервисов
compose.yaml                 запуск контейнеров
.env.example                 пример конфигурации
```

Исходный файл данных — `data/raw/bank-additional-full.csv`. При обучении удаляются дубликаты и столбец `duration`: длительность звонка неизвестна до его окончания и не подходит для предсказания перед контактом с клиентом. Значение `unknown` считается пропуском, а `pdays` преобразуется в признак наличия предыдущего контакта (`999` означает отсутствие контакта). Статистические преобразования, включая заполнение пропусков, кодирование категорий и масштабирование, обучаются внутри `sklearn.Pipeline` и сохраняются вместе с моделью.

## Первый запуск

Нужны Docker с Docker Compose и файл данных по пути выше. В корне проекта выполните:

```bash
cp .env.example .env
docker compose up -d --build inference
```

В новом проекте регистр пока пуст. Inference запустится, но `/health` будет возвращать `503 Model not loaded` до первого успешного обучения. Запустите Train:

```bash
docker compose run --rm train
```

Train оставляет последние `VALIDATION_SIZE` строк для валидации, сохраняя исходный порядок данных. Если ROC-AUC ниже `MIN_ROC_AUC`, задача завершается с ошибкой, модель не сохраняется и активная версия не меняется. Если порог пройден, модель сохраняется как новый `.joblib`-файл, после чего Train отправляет запрос на `/models/activate`. Inference загружает новую модель без перезапуска.

Проверьте состояние:

```bash
curl -i http://127.0.0.1:8001/health
```

После обучения ожидается `200 OK` и имя активной модели. Если порт изменён в `.env`, используйте значение `INFERENCE_HOST_PORT` вместо `8001`. Документация API доступна по адресу `http://127.0.0.1:8001/docs`.

Для повторного обучения после обновления CSV снова выполните `docker compose run --rm train`. Остановить постоянно работающий сервис можно командой `docker compose down`.

## Предсказание

`POST /predict` принимает признаки одного клиента. Поля `duration` и `y` передавать не нужно.

```bash
curl -X POST http://127.0.0.1:8001/predict \
  -H 'Content-Type: application/json' \
  -d '{
    "age": 40,
    "job": "admin.",
    "marital": "married",
    "education": "university.degree",
    "default": "no",
    "housing": "yes",
    "loan": "no",
    "contact": "cellular",
    "month": "may",
    "day_of_week": "mon",
    "campaign": 1,
    "pdays": 999,
    "previous": 0,
    "poutcome": "nonexistent",
    "emp.var.rate": 1.1,
    "cons.price.idx": 93.9,
    "cons.conf.idx": -42.0,
    "euribor3m": 4.8,
    "nr.employed": 5195.8
  }'
```

Форма ответа:

```json
{"prediction": 0, "probability": 0.04}
```

Число в примере ответа иллюстративное: результат зависит от активной версии модели. Pydantic проверяет типы, категории и границы числовых признаков (`age`: 17–120, `campaign`: от 1), а также отклоняет `NaN` и бесконечности. Некорректный запрос получает HTTP `422`; если модель не загружена, `/predict` возвращает `503`.

## Модели и API

- `GET /health` — `200` и имя версии при загруженной модели; `503`, если модели нет.
- `POST /predict` — предсказание и вероятность положительного класса.
- `POST /models/activate` — загрузка уже сохранённой версии из регистра. Train вызывает его автоматически.

Для ручной активации укажите **имя файла** из `model_registry/`, без полного пути:

```bash
curl -X POST http://127.0.0.1:8001/models/activate \
  -H 'Content-Type: application/json' \
  -d '{"model_name":"model_YYYYMMDDTHHMMSSffffffZ.joblib"}'
```

Замените имя в примере на существующий файл. Перед сменой активной версии Inference проверяет, что файл загружается и содержит обученный `sklearn.Pipeline`. Текущая модель остаётся доступной, если новая не прошла проверку. Имя активной версии хранится в `model_registry/active_model.txt`; файлы моделей и локальный `.env` не добавляются в Git.

## Конфигурация

Настройки находятся в `.env` и загружаются через `pydantic-settings` с проверкой типов и допустимых значений. Полный список и значения для первого запуска приведены в `.env.example`.

| Переменная | Назначение |
| --- | --- |
| `TRAIN_DATA_PATH` | Путь к CSV внутри контейнера Train |
| `MODEL_REGISTRY_DIR` | Общий каталог версий моделей |
| `ACTIVE_MODEL_PATH` | Необязательный путь к модели при отсутствии записи об активной версии |
| `MIN_ROC_AUC` | Минимальный ROC-AUC для активации новой модели |
| `VALIDATION_SIZE` | Доля последних строк для валидации |
| `MODEL_RANDOM_STATE`, `MODEL_C`, `MODEL_SOLVER`, `MODEL_MAX_ITER`, `MODEL_L1_RATIO` | Параметры логистической регрессии |
| `INFERENCE_URL` | Адрес Inference для запроса активации из Train |
| `INFERENCE_TIMEOUT_SECONDS`, `ACTIVATION_MAX_ATTEMPTS`, `ACTIVATION_RETRY_DELAY_SECONDS` | Таймаут и повторные попытки активации |
| `INFERENCE_HOST_PORT` | Порт API на локальном компьютере |
| `COMPOSE_PROJECT_NAME` | Имя проекта Docker Compose |
| `LOG_LEVEL` | Уровень логирования |

После изменения `.env` пересоздайте соответствующий контейнер, чтобы он получил новые значения. Train создаётся заново при каждом `docker compose run --rm train`.

## Тесты

Для локального запуска тестов нужен `uv`:

```bash
uv sync
uv run pytest -q
```

Тесты проверяют порог качества перед деплоем, активацию модели, работу регистра, предсказание, валидацию запросов и настроек. Они используют временные файлы и подмены и не переключают модель в работающем сервисе.
